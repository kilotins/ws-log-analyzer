Architecture3/10

Grade: A

Core Design

  • Two-file split: wslog.py is stdlib-only and handles all parsing, classification, and report generation. app.py is the Streamlit GUI layer that imports from wslog.py.
  • Zero required dependencies: Core runs on Python 3.9+ stdlib. anthropic, google-generativeai, openai, streamlit, pytest are all optional.
  • Precompute layer: precompute_analysis() runs all analysis functions once and caches results, avoiding redundant computation in the GUI.

AI Architecture (Post-Milestone 2)

  • _AI_MODELS dict: Maps display names to {provider, model_id} — 7 models across 3 providers + Swedish Chef mode
  • _PROVIDER_CONFIG dict: Centralizes per-provider cache keys, history files, API key fields, and save functions
  • _run_ai_analysis(): Common orchestrator handling cache lookup, API call dispatch, history recording, error display, cost calculation
  • _API_CALLERS dispatch: Maps provider names to API caller functions, each returning (answer, usage) tuples
  • Streaming: Claude uses client.messages.stream(), OpenAI uses stream=True. Both render tokens incrementally via st.empty() placeholder.

File Organization

app.py at 1,983 lines is approaching the 2,000-line threshold for splitting. Current organization is logical (setup → helpers → rendering → AI → realtime → audit → main), but a future split into ai_providers.py, renderers.py, sidebar.py would improve maintainability.

Security4/10

Grade: A (up from A-)

Secret Redaction

  • 5 regex patterns: bearer tokens, key=value pairs, JSON secrets, connection strings, JWTs
  • Applied via redact() on all event text during parsing — no raw secrets in output
  • NEW: 24 false-positive tests ensure normal log text (WAS codes, exception names, URL parameters, JSON keys) is not over-redacted

Prompt Injection Defense

  • _sanitize_prompt_input() strips XML-like delimiter tags and escapes entities
  • System prompt explicitly warns the AI model about untrusted input
  • User queries and log excerpts wrapped in <user_query> / <log_excerpt> XML tags

Path Safety

  • _is_safe_rt_path() blocks /etc, /proc, /sys, /dev and only allows .log/.gz/.txt/.out extensions
  • Unit tested with both valid and malicious paths

API Key Storage

  • Keys stored via keyring with fallback to environment variables
  • Displayed as type="password" in the sidebar
  • Consolidated keychain helpers (_load_keychain() / _save_keychain())

Minor Observations

  • unsafe_allow_html=True used for realtime log monitor — content escaped via html.escape(), safe
  • Realtime monitor allows .out extension — could be tightened to .log only for maximum safety
  • No symlink check in _is_safe_rt_path() — consider adding p.is_symlink() guard

Remaining Issues9/10

These are minor issues that don't affect the overall grade significantly:

Medium Priority

  • _rt_live_view() at 284 lines: The realtime monitor function handles UI rendering, state management, and file polling in one function. Should be split into _rt_status_panel(), _rt_controls(), and _rt_render_buffer().
  • Missing symlink check: _is_safe_rt_path() doesn't check p.is_symlink() — could allow path traversal via symlinks.
  • E2e test flakiness: 6 of 18 Playwright tests fail due to timing issues (element visibility, click timeouts). Need wait_for_selector or increased timeouts.
  • No API rate limiting: Multiple rapid AI calls could exhaust API budgets.

Low Priority

  • Bare except Exception: A few catch-all blocks in wslog.py that should be narrowed to specific exceptions.
  • Type hints in app.py: Most functions lack type annotations (unlike wslog.py which is fully typed).
  • History wrapper functions: 6 thin wrappers (_load_history, _save_history, etc.) could use a factory pattern, though the current approach is clear and explicit.
  • Multi-file audit scope: Currently audits all Python files. Could allow selecting which files to include.
  • .out extension in realtime monitor: Could be tightened to .log only.
