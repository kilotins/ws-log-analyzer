2. Getting Started 1 min UPLOAD
Narration

Getting started is simple. On the Home page you have a drag-and-drop file upload area. LogPilot accepts plain .log files, gzipped logs, and ZIP archives containing multiple files. You can upload logs from multiple systems at once — for example, an nginx access log, a Java app server log, and a database log all together. LogPilot automatically detects the format of each file. Supported formats include WAS, nginx, Log4j, JSON structured logs, Python logging, syslog, Enonic XP, Kubernetes CRI-O, Docker JSON, DataPower, Tomcat, and PostgreSQL. Once you have your files selected, just click Analyze.

Show on screen
  • Drag one or more log files onto the upload drop zone
  • Show that multiple files from different systems are accepted simultaneously
  • Optionally drag in a screenshot (e.g., a 502 error page) for AI context
  • Point out the "Add screenshots for AI context" area below the main upload
  • Describe symptoms in the text box: "Getting 502 errors, database connections timing out"
  • Click the Analyze button — watch the spinner
Pro tip

You can also point LogPilot at a folder — it will recursively scan and find all log files, including rotated and gzipped logs. Useful for analyzing a full /var/log directory.

3. Overview Dashboard 1 min OVERVIEW
Narration

After analysis, the Overview Dashboard gives you an immediate picture of what's in your logs. At the top you see the severity distribution — how many INFO, WARNING, ERROR, and CRITICAL events were found. Below that, the top message codes: HTTP status codes, WAS message prefixes, exception class names — ranked by frequency. Signal tags highlight the major problem categories: things like HTTP errors, database connection pool exhaustion, SSL/TLS failures, out-of-memory events, and Kubernetes pod issues. And at the bottom, a per-file breakdown so you can immediately see which system is generating the most noise.

4. Causes & Fixes 1.5 min HEURISTICS
Narration

The Causes and Fixes page is where LogPilot's offline intelligence shines. Without any AI and without a network connection, LogPilot runs 68 built-in heuristic patterns against your events. These patterns cover everything from database connection pool exhaustion and SSL certificate expiry, to OOM killer events, hung thread detection, and HTTP upstream failures. Each finding is grouped into incident groups — for example, a root-cause event linked to its downstream cascading failures and any concurrent issues happening at the same time. Every finding comes with a specific fix suggestion, a confidence score, and the exact log lines that triggered it. This alone can cut your triage time dramatically, even before you involve AI.

  • Highlight the confidence score (e.g., 0.87) next to the finding

Key talking point

This works with zero dependencies — no AI API key required. LogPilot can run completely airgapped. The 68 heuristics encode years of WebSphere, nginx, Java, and infrastructure operational knowledge.

5. AI Analysis 2 min MAIN FEATURE AI
Narration

Now for the main event — AI Analysis. This is where LogPilot goes from triage tool to incident analyst. On the AI Analysis page, you first describe the symptoms you're seeing in plain language. Something like: "We're getting 502 errors from nginx, the app is timing out on database calls, and we had an OOM event around 2 PM." LogPilot reads that description and automatically extracts noise exclusions — if you say "don't focus on the SSL warnings", those get filtered out before the AI sees anything. Then you choose your AI model. LogPilot supports Claude from Anthropic, Gemini from Google, OpenAI's GPT models, and local models through Ollama or LM Studio — so you can run it entirely on-premises if you need to. There's a noise filter slider to strip out repetitive low-value events before they consume tokens. Hit Analyze and within seconds the AI produces a full incident report: what happened, a unified error timeline correlating events across all your systems, the root cause, a cascade analysis showing how one failure triggered the next, which systems were affected, and a prioritized action plan of what to do right now.

8. Trace to Code 1.5 min NEW
Narration

Trace to Code connects the dots between your log errors and your actual source code. When LogPilot finds stacktraces in your logs, it extracts the file names and line numbers, then searches your linked source code repository to find the matching code. You see the exact code that triggered each error — with syntax highlighting and context.

But here's where it gets powerful: when you run the AI Analysis, the matched source code is included in the AI prompt. The AI doesn't just tell you what went wrong — it can see your code and suggest specific fixes. Those suggestions appear right on the Trace to Code page, next to each matched file. It's like having a senior developer reviewing your code alongside the production logs.

10. Jira & Confluence Integration 1 min JIRA
Narration

Once you have your incident analysis, the next step is usually creating work items. The Jira integration lets you auto-generate Jira tickets directly from the incident groups found by the heuristics. Each ticket is pre-filled with the finding, the affected system, the fix suggestion, and the relevant log evidence. LogPilot supports eight team mappings — so it routes tickets to the right team automatically based on the system involved: infrastructure tickets to the infra team, database findings to the DBA team, and so on. If you don't have a live Jira connection, you can export the tickets as CSV for bulk import. And for documentation, you can publish the full analysis report directly to Confluence using the REST API.

12. Key Differentiators 30 sec WHY LOGPILOT
Narration

Let me close the feature tour with what sets LogPilot apart. First — zero required dependencies. The entire core runs on Python's standard library. No pip install required for basic analysis. It ships as a single package. Second — 14 log format plugins with automatic detection. You don't configure anything. Third — it works completely offline. The heuristic engine runs without any network access or API keys. AI is additive, not required. Fourth — secret redaction is built in. API keys, passwords, and bearer tokens are automatically stripped from all event text before they appear in any report or get sent to an AI. And fifth — it's built to be extended. Adding a new log format plugin is a matter of implementing a small Python protocol class. The architecture is documented and the plugin interface is clean.
