2. V1 Scope — What’s In, What’s Out

The V1 rule

V1 must do everything the current Streamlit app does, but on the new architecture. Plus: workspaces, API, and auth. Minus: nothing the current app doesn’t already do. No new analysis features until the platform is solid.

In Scope (V1)

FeatureAcceptance Criteria
File upload Upload 1–20 log files (plain text + .gz) via web UI or API. Drag-and-drop. Max 100 MB per file, 500 MB per session.
Format auto-detection All 11 format plugins working: WAS, JSON, nginx, Log4j, Python, syslog, Enonic XP, CRI-O, IBM DataPower (new), Tomcat/Catalina (new — java.util.logging format), PostgreSQL (new — currently misidentified as Log4j). Same detection quality as current app + 3 new formats.
Parsing & classification Events parsed with level, code, exception, root_cause, tags, trace IDs. Secret redaction. Same output as current parse_file().
Analysis Summary, timeline histogram, likely causes (83 heuristics), correlations (17 rules), incident grouping (7 groups), cascade detection, evidence extraction, sample selection.
AI explanation Incident AI assistant with Claude, OpenAI, Gemini, and local model support. Streaming responses. BYO API key. Prompt injection protection.
Reports Export as Markdown, HTML, JSON, PDF. Include AI content if available.
Organizations & workspaces Org → workspace → members model. Workspace data isolation. Settings inheritance (org → workspace).
Auth Three modes: NoAuth (laptop), local password, OIDC (Azure AD / Google). Auto-created “Personal” workspace in NoAuth mode.
REST API Ingest, sessions, analysis results, AI explain, reports. API keys per workspace with scopes. OpenAPI docs auto-generated.
Background jobs Parse and analyze in background for files > 50 MB. Status polling or WebSocket notification.
Adapter layer SQLite + filesystem (laptop) and Postgres + S3 (team/SaaS). Both tested and working.
Docker deployment Single-container (laptop) and Docker Compose (team) working out of the box.

Out of Scope (V2+)

FeatureWhy deferred
Rust parse enginePython parser is fast enough for V1 volumes. Rust when customers hit file-size limits.
ClickHouse event storagePostgres JSONB + DuckDB handles V1 scale. ClickHouse when we exceed ~10M events/workspace.
RAG (incident history search)Needs accumulated AI explanations to index. Ship V1 first, add RAG when workspaces have history.
Source code lookupOptional enrichment. Core product must work without it.
Webhooks (outbound)API ingest is V1. Outbound webhooks (Slack/PagerDuty notifications) are V2.
Helm chart / KubernetesDocker Compose is enough for V1. Helm when enterprise customers need HA.
Billing / paymentFirst customers are manual. Stripe integration when we have 20+ paying customers.
Log streaming (tail -f)Different product. V1 handles uploaded files.
SCIM provisioningEnterprise feature. OIDC is enough for V1.
Custom heuristic editor UIYAML files + Git is fine for V1.
V1 definition of done

A user can: create an account (or use locally without one) → upload log files → see incident analysis → get AI explanation → export report → invite team members to a shared workspace → push logs via API. All of this works on a laptop, a team server, or our SaaS.

5. Core Engine Migration Plan

The core engine (logpilot/) moves to the new repo as /core. This is the most important step — get it wrong and we lose the 5,800 lines of tested, working code.

Migration Strategy: Copy, Don’t Rewrite

Rule

Copy files verbatim. Run existing tests. Only refactor what breaks. Do not “improve” code during migration — that’s how bugs are introduced and weeks are lost.

File Mapping

Required Refactors (Minimal)

FileChangeWhy
ai.py Extract prompt builders into pure functions. Make API calls async. Remove Streamlit imports. FastAPI is async. Prompt construction must be separate from API calling so the API layer controls the provider call.
parser.py Remove file-cache logic (cache moves to storage adapter). Keep parse_file() and parse_file_iter() signatures. Caching is now the platform’s responsibility, not the parser’s.
event.py Add severity_int property. Add Pydantic model for API serialization. API needs typed serialization. severity_int avoids string comparisons in analysis code.
Import paths from logpilot.parser import ... → from core.parser import ... New package name.

Do not lose skills during migration

Skills represent months of accumulated domain knowledge (83 heuristics, 8 format plugins, security patterns, performance analysis). The migration checklist must include a skills file count verification. If the count is wrong, stop and investigate.

Technical Debt Prevention

The new repo starts clean — no debt carried forward

The whole point of rebuilding is to escape accumulated technical debt. Be ruthless about what comes over. Copy the logic, not the workarounds.

What we take (clean code)

  • Core engine (logpilot/) — parser, analysis, heuristics, formats, reports. These are well-tested and well-structured.
  • Skills and YAML heuristics — domain knowledge, format-agnostic.
  • Test cases — the assertions and fixtures, not the test infrastructure.

What we do NOT take

Debt itemWhere it livesWhat we do instead
Streamlit GUI code app.py, app_*.py (~3,900 lines) Replace entirely with React + FastAPI. Zero Streamlit code in new repo.
Session state as database st.session_state throughout app_*.py Proper database (SQLite/Postgres) + API state management (Tanstack Query).
File-based caching ai_responses.json, cache/parsed_*.json.gz Database-backed caching. No JSON files as persistence.
Synchronous AI calls app_ai.py blocking calls Async AI calls with proper streaming via SSE.
Global mutable state Module-level dicts, in-place mutation of LogEvent fields Immutable data flow. Events are enriched in pipeline stages, not mutated in place.
Inconsistent field population ts_utc set by sort, sample_label set by pick_samples All fields populated during parsing/classification. No late-assignment.
Duplicated classify_event() In both parser.py and format plugins Single classify path: format plugin classifies, parser delegates.
Untyped analysis results Plain dict returns from analysis functions Typed Pydantic models for all analysis results.
Hardcoded cache paths cache/, .api_keys.json, ai_responses.json All persistence through adapter interfaces. No hardcoded file paths.
Provider-specific API call code in UI app_ai.py mixes UI rendering with API calls Clean separation: API layer calls providers, frontend renders responses.

Rules for the New Repo

  • No print() statements — use structlog for all output
  • No hardcoded file paths — all storage through adapters
  • No synchronous I/O in API routes — async everywhere
  • No untyped returns — every function returns a typed model or primitive
  • No global mutable state — dependency injection for everything
  • No secrets in code — all config via environment variables / settings
  • Tests from day one — no feature merged without test coverage
  • Linting enforced in CI — Ruff (Python) + ESLint (TypeScript), no warnings allowed

6. Database Schema (V1)

-- ========================================
-- ORGANIZATIONS & USERS
-- ========================================

CREATE TABLE organizations (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    slug        text UNIQUE NOT NULL,
    plan        text NOT NULL DEFAULT 'free',
    settings    jsonb NOT NULL DEFAULT '{}',
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE users (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    email           text UNIQUE NOT NULL,
    name            text,
    password_hash   text,                  -- null for OIDC users
    auth_provider   text NOT NULL DEFAULT 'local',
    auth_subject    text,                  -- external IdP subject
    created_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE org_memberships (
    org_id      uuid NOT NULL REFERENCES organizations ON DELETE CASCADE,
    user_id     uuid NOT NULL REFERENCES users ON DELETE CASCADE,
    role        text NOT NULL DEFAULT 'member',
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (org_id, user_id)
);

-- ========================================
-- WORKSPACES
-- ========================================

CREATE TABLE workspaces (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id      uuid NOT NULL REFERENCES organizations ON DELETE CASCADE,
    name        text NOT NULL,
    slug        text NOT NULL,
    settings    jsonb NOT NULL DEFAULT '{}',
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE(org_id, slug)
);

CREATE TABLE workspace_memberships (
    workspace_id uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    user_id      uuid NOT NULL REFERENCES users ON DELETE CASCADE,
    role         text NOT NULL DEFAULT 'member',
    created_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (workspace_id, user_id)
);

-- ========================================
-- API KEYS
-- ========================================

CREATE TABLE api_keys (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    name          text NOT NULL,
    key_hash      text NOT NULL,
    key_prefix    text NOT NULL,           -- "lp_live_a3f2" for display
    scopes        text[] NOT NULL,
    expires_at    timestamptz,
    created_by    uuid REFERENCES users,
    created_at    timestamptz NOT NULL DEFAULT now(),
    last_used_at  timestamptz
);
CREATE INDEX idx_api_keys_prefix ON api_keys(key_prefix);

-- ========================================
-- SESSIONS & UPLOADS
-- ========================================

CREATE TABLE sessions (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    name          text,
    status        text NOT NULL DEFAULT 'created',  -- created|parsing|analyzing|ready|error
    created_by    uuid REFERENCES users,
    created_at    timestamptz NOT NULL DEFAULT now(),
    updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_sessions_workspace ON sessions(workspace_id, created_at DESC);

CREATE TABLE uploads (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    filename    text NOT NULL,
    storage_key text NOT NULL,             -- object store key
    size_bytes  bigint NOT NULL,
    format      text,                       -- detected format name
    event_count int,                        -- populated after parsing
    created_at  timestamptz NOT NULL DEFAULT now()
);

-- ========================================
-- ANALYSIS RESULTS
-- ========================================

CREATE TABLE analyses (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    results     jsonb NOT NULL,             -- full precomputed analysis
    incidents   jsonb NOT NULL DEFAULT '[]', -- incident groups array
    summary     jsonb NOT NULL DEFAULT '{}', -- event counts, level breakdown
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE(session_id)                    -- one analysis per session
);

-- ========================================
-- AI CONVERSATIONS
-- ========================================

CREATE TABLE ai_conversations (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    user_id     uuid NOT NULL REFERENCES users,
    provider    text NOT NULL,
    model       text NOT NULL,
    prompt_hash text NOT NULL,              -- for cache dedup
    user_prompt text NOT NULL,              -- redacted prompt sent to AI
    response    text NOT NULL,
    input_tokens  int,
    output_tokens int,
    cost_usd    numeric(10,6),
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_ai_conv_session ON ai_conversations(session_id, created_at);

-- ========================================
-- AUDIT LOG
-- ========================================

CREATE TABLE audit_log (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces,
    user_id       uuid REFERENCES users,
    action        text NOT NULL,            -- "session.create", "ai.explain", "export.pdf"
    resource_type text,                     -- "session", "workspace", "api_key"
    resource_id   uuid,
    metadata      jsonb DEFAULT '{}',
    created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_workspace ON audit_log(workspace_id, created_at DESC);

-- ========================================
-- ROW-LEVEL SECURITY
-- ========================================

ALTER TABLE sessions ENABLE ROW LEVEL SECURITY;
ALTER TABLE uploads ENABLE ROW LEVEL SECURITY;
ALTER TABLE analyses ENABLE ROW LEVEL SECURITY;
ALTER TABLE ai_conversations ENABLE ROW LEVEL SECURITY;
ALTER TABLE audit_log ENABLE ROW LEVEL SECURITY;

-- Policy example (applied to all workspace-scoped tables)
CREATE POLICY workspace_isolation ON sessions
    USING (workspace_id = current_setting('app.current_workspace_id')::uuid);

SQLite Equivalent

The SQLite adapter uses the same table structure but without RLS (single-user, no isolation needed), without gen_random_uuid() (uses Python-generated UUIDs), and with TEXT instead of uuid type. The adapter translates between the two.

V1 Non-Functional Requirements

Observability: LogPilot Must Log Itself

A log analysis tool with bad logging is a credibility disaster

If we run LogPilot as SaaS and can’t debug our own production issues, we have a trust problem. Structured logging, request tracing, and error tracking must be built in from day one — not bolted on later.

ConcernImplementationPhase
Structured application logs JSON-formatted logs via Python structlog. Every log entry includes: timestamp, level, request_id, workspace_id, user_id, action, duration_ms. No print statements. Phase 1
Request tracing Unique request_id generated per API request (middleware). Propagated to all service calls, background jobs, and AI provider calls. Returned in response headers (X-Request-Id). Phase 1
Error tracking Unhandled exceptions captured with full context (request_id, workspace_id, user_id, stack trace). In SaaS: sent to Sentry or similar. Self-service: logged to structured log. Phase 2
Performance metrics Key timings logged per request: parse_duration_ms, analysis_duration_ms, ai_call_duration_ms. Slow requests (> 5s) logged at WARN level. Phase 2
Health and readiness GET /health (is the process alive), GET /ready (are DB + Redis connected). Used by Docker health checks and Kubernetes probes. Phase 1
Audit trail Already in DB schema: audit_log table. Every significant action (session create, AI call, export, member invite) is recorded with workspace, user, timestamp. Phase 3
AI call logging Every AI provider call logged: provider, model, input/output tokens, cost, duration, success/failure. For debugging and cost monitoring. Already in ai_conversations table. Phase 2
Background job logging Job start, progress, completion, failure logged with job_id, session_id, duration. Failed jobs logged at ERROR with full context for debugging. Phase 3

Eat your own dog food

LogPilot’s own logs should be parseable by LogPilot. If we can’t analyze our own production incidents with our own tool, we have work to do. This is both a quality signal and a powerful demo: “Here’s LogPilot analyzing its own logs.”

Product Design Principles

PrincipleWhat it means in practice
Cascade visualization is the killer feature “System A failed at 10:15, causing 47 errors in System B at 10:16–10:18, leading to timeouts in System C at 10:19.” No other tool shows this. ChatGPT cannot do it. Make it the centerpiece of the demo and the analysis view.
The incident report is an artifact Every analysis should produce a professional, shareable report. “Incident Report — March 20, 2026 — Database Connection Cascade.” Branded, complete, ready for post-mortem or management. This artifact spreads awareness of the tool.
Empty state is the first impression Before any logs are uploaded: show a sample analysis (one click to explore), not an empty page with an upload button. “What kind of logs do you have?” → select format → see what LogPilot finds in that type.
Errors are opportunities “Could not parse file” is a failure. “This looks like a custom format. LogPilot supports WAS, nginx, Log4j, Python, syslog, Enonic XP, and Kubernetes. Learn how to add a custom format.” — that’s an opportunity.
CLI is a first-class citizen logpilot analyze ./logs/ --format markdown and logpilot analyze ./logs/ --explain --provider claude must work. Developers who live in the terminal will not open a web app. The CLI is also the fastest path to CI/CD integration.
Use real incidents in every demo Never demo with synthetic logs. Take anonymized incidents from real consulting work. Authenticity is visible — and if the demo doesn’t impress with real data, it’s a product problem, not a demo problem.
