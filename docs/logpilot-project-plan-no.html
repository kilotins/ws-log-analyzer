2. V1-omfang — Hva er med, hva er utenfor

V1-regelen

V1 må gjøre alt den nåværende Streamlit-appen gjør, men på den nye arkitekturen. I tillegg: arbeidsområder, API og autentisering. Minus: ingenting den nåværende appen ikke allerede gjør. Ingen nye analysefunksjoner før plattformen er solid.

Inkludert (V1)

FunksjonAkseptansekriterier
Filopplasting Last opp 1–20 loggfiler (ren tekst + .gz) via webgrensesnitt eller API. Dra-og-slipp. Maks 100 MB per fil, 500 MB per sesjon.
Automatisk formatgjenkjenning Alle 11 format-plugins fungerer: WAS, JSON, nginx, Log4j, Python, syslog, Enonic XP, CRI-O, IBM DataPower (ny), Tomcat/Catalina (ny — java.util.logging-format), PostgreSQL (ny — identifiseres nå feilaktig som Log4j). Samme gjenkjenningskvalitet som nåværende app + 3 nye formater.
Parsing og klassifisering Hendelser parset med nivå, kode, unntak, rotårsak, tagger, spor-ID-er. Hemmelighetsmaskering. Samme resultat som nåværende parse_file().
Analyse Sammendrag, tidslinjehistogram, sannsynlige årsaker (83 heuristikker), korrelasjoner (17 regler), hendelsesgruppering (7 grupper), kaskadedeteksjon, bevisekstraksjon, utvalg av eksempler.
AI-forklaring Hendelse-AI-assistent med Claude, OpenAI, Gemini og lokal modellstøtte. Strømmende svar. Medbring egen API-nøkkel. Beskyttelse mot prompt-injeksjon.
Rapporter Eksporter som Markdown, HTML, JSON, PDF. Inkluder AI-innhold hvis tilgjengelig.
Organisasjoner og arbeidsområder Org → arbeidsområde → medlemmer-modell. Dataisolasjon per arbeidsområde. Innstillingsarv (org → arbeidsområde).
Autentisering Tre moduser: NoAuth (laptop), lokalt passord, OIDC (Azure AD / Google). Automatisk opprettet «Personlig» arbeidsområde i NoAuth-modus.
REST API Inntak, sesjoner, analyseresultater, AI-forklaring, rapporter. API-nøkler per arbeidsområde med rettigheter. OpenAPI-dokumentasjon autogenerert.
Bakgrunnsjobber Parse og analyser i bakgrunnen for filer > 50 MB. Statuspolling eller WebSocket-varsling.
Adapterlag SQLite + filsystem (laptop) og Postgres + S3 (team/SaaS). Begge testet og fungerende.
Docker-distribusjon Enkel-container (laptop) og Docker Compose (team) fungerer rett ut av boksen.

V1 definisjon av ferdig

En bruker kan: opprette en konto (eller bruke lokalt uten en) → laste opp loggfiler → se hendelsesanalyse → få AI-forklaring → eksportere rapport → invitere teammedlemmer til et delt arbeidsområde → sende logger via API. Alt dette fungerer på en laptop, en teamserver eller vår SaaS.

5. Migreringsplan for kjernemotor

Kjernemotoren (logpilot/) flyttes til det nye repoet som /core. Dette er det viktigste steget — gjør du det feil, mister vi de 5 800 linjene med testet, fungerende kode.

Migreringsstrategi: Kopier, ikke skriv om

Regel

Kopier filer ordrett. Kjør eksisterende tester. Refaktorer bare det som bryter. Ikke «forbedre» kode under migrering — det er slik feil introduseres og uker går tapt.

Filkartlegging

# Old repo (ws-log-analyzer)         # New repo (logpilot-platform)

logpilot/parser.py             →    core/parser.py
logpilot/analysis.py           →    core/analysis.py
logpilot/heuristics.py         →    core/heuristics.py
logpilot/_heuristics_fallback.py →  core/_heuristics_fallback.py
logpilot/discovery.py          →    core/discovery.py

logpilot/ai.py                 →    core/ai.py              # + async refactor
skills/                        →    core/skills/            # YAML heuristic files

Nødvendige refaktoreringer (minimale)

FilEndringHvorfor
ai.py Ekstraher prompt-byggere til rene funksjoner. Gjør API-kall asynkrone. Fjern Streamlit-importer. FastAPI er asynkront. Prompt-konstruksjon må være adskilt fra API-kalling slik at API-laget kontrollerer leverandørkallet.
parser.py Fjern fil-cache-logikk (cache flyttes til lagringsadapter). Behold parse_file() og parse_file_iter()-signaturer. Caching er nå plattformens ansvar, ikke parserens.
event.py Legg til severity_int-egenskap. Legg til Pydantic-modell for API-serialisering. API trenger typet serialisering. severity_int unngår strengsammenligninger i analysekode.
Importstier from logpilot.parser import ... → from core.parser import ... Nytt pakkenavn.

Forebygging av teknisk gjeld

Det nye repoet starter rent — ingen gjeld føres videre

Hele poenget med å bygge på nytt er å unnslippe akkumulert teknisk gjeld. Vær nådeløs med hva som tas med. Kopier logikken, ikke løsningene.

Hva vi tar med (ren kode)

  • Kjernemotor (logpilot/) — parser, analyse, heuristikker, formater, rapporter. Disse er godt testet og godt strukturert.
  • Skills og YAML-heuristikker — domenekunnskap, formatuavhengig.
  • Testtilfeller — påstandene og testdataene, ikke testinfrastrukturen.

Hva vi IKKE tar med

GjeldselementHvor det borHva vi gjør i stedet
Streamlit GUI-kode app.py, app_*.py (~3 900 linjer) Erstattes helt med React + FastAPI. Null Streamlit-kode i nytt repo.
Sesjonstilstand som database st.session_state gjennom app_*.py Ordentlig database (SQLite/Postgres) + API-tilstandshåndtering (Tanstack Query).
Filbasert caching ai_responses.json, cache/parsed_*.json.gz Databasestøttet caching. Ingen JSON-filer som persistens.
Synkrone AI-kall app_ai.py blokkerende kall Asynkrone AI-kall med ordentlig strømming via SSE.
Global muterbar tilstand Modulnivå-dicts, mutasjon på stedet av LogEvent-felt Umuterbar dataflyt. Hendelser berikes i pipeline-steg, ikke muteres på stedet.
Inkonsistent feltpopulering ts_utc satt av sortering, sample_label satt av pick_samples Alle felt populeres under parsing/klassifisering. Ingen sen tildeling.

Utypede analyseresultater Vanlige dict-returer fra analysefunksjoner Typede Pydantic-modeller for alle analyseresultater.
Hardkodede cache-stier cache/, .api_keys.json, ai_responses.json All persistens gjennom adaptergrensesnitt. Ingen hardkodede filstier.
Leverandørspesifikk API-kallkode i UI app_ai.py blander UI-rendering med API-kall Rent skille: API-lag kaller leverandører, frontend rendrer svar.

Regler for det nye repoet

  • Ingen print()-setninger — bruk structlog for all utdata
  • Ingen hardkodede filstier — all lagring gjennom adaptere
  • Ingen synkron I/O i API-ruter — asynkront overalt
  • Ingen utypede returer — hver funksjon returnerer en typet modell eller primitiv
  • Ingen global muterbar tilstand — dependency injection for alt
  • Ingen hemmeligheter i kode — all konfigurasjon via miljøvariabler / innstillinger
  • Tester fra dag én — ingen funksjon merges uten testdekning
  • Linting håndheves i CI — Ruff (Python) + ESLint (TypeScript), ingen advarsler tillatt

-- ORGANISASJONER OG BRUKERE
-- ========================================

CREATE TABLE organizations (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    slug        text UNIQUE NOT NULL,
    plan        text NOT NULL DEFAULT 'free',
    settings    jsonb NOT NULL DEFAULT '{}',
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE users (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    email           text UNIQUE NOT NULL,
    name            text,
    password_hash   text,                  -- null for OIDC users
    auth_provider   text NOT NULL DEFAULT 'local',
    auth_subject    text,                  -- external IdP subject
    created_at      timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE org_memberships (
    org_id      uuid NOT NULL REFERENCES organizations ON DELETE CASCADE,
    user_id     uuid NOT NULL REFERENCES users ON DELETE CASCADE,
    role        text NOT NULL DEFAULT 'member',
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (org_id, user_id)
);

-- ========================================
-- ARBEIDSOMRÅDER
-- ========================================

CREATE TABLE workspaces (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id      uuid NOT NULL REFERENCES organizations ON DELETE CASCADE,
    name        text NOT NULL,
    slug        text NOT NULL,
    settings    jsonb NOT NULL DEFAULT '{}',
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE(org_id, slug)
);

CREATE TABLE workspace_memberships (
    workspace_id uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    user_id      uuid NOT NULL REFERENCES users ON DELETE CASCADE,
    role         text NOT NULL DEFAULT 'member',
    created_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (workspace_id, user_id)
);

-- ========================================
-- API-NØKLER
-- ========================================

CREATE TABLE api_keys (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    name          text NOT NULL,
    key_hash      text NOT NULL,
    key_prefix    text NOT NULL,           -- "lp_live_a3f2" for display
    scopes        text[] NOT NULL,
    expires_at    timestamptz,
    created_by    uuid REFERENCES users,
    created_at    timestamptz NOT NULL DEFAULT now(),
    last_used_at  timestamptz
);
CREATE INDEX idx_api_keys_prefix ON api_keys(key_prefix);

-- ========================================
-- SESJONER OG OPPLASTINGER
-- ========================================

CREATE TABLE sessions (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces ON DELETE CASCADE,
    name          text,
    status        text NOT NULL DEFAULT 'created',  -- created|parsing|analyzing|ready|error
    created_by    uuid REFERENCES users,
    created_at    timestamptz NOT NULL DEFAULT now(),
    updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_sessions_workspace ON sessions(workspace_id, created_at DESC);

CREATE TABLE uploads (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    filename    text NOT NULL,
    storage_key text NOT NULL,             -- object store key
    size_bytes  bigint NOT NULL,
    format      text,                       -- detected format name
    event_count int,                        -- populated after parsing
    created_at  timestamptz NOT NULL DEFAULT now()
);

-- ========================================
-- ANALYSERESULTATER
-- ========================================

CREATE TABLE analyses (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    results     jsonb NOT NULL,             -- full precomputed analysis
    incidents   jsonb NOT NULL DEFAULT '[]', -- incident groups array
    summary     jsonb NOT NULL DEFAULT '{}', -- event counts, level breakdown
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE(session_id)                    -- one analysis per session
);

-- ========================================
-- AI-SAMTALER
-- ========================================

CREATE TABLE ai_conversations (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id  uuid NOT NULL REFERENCES sessions ON DELETE CASCADE,
    user_id     uuid NOT NULL REFERENCES users,
    provider    text NOT NULL,
    model       text NOT NULL,
    prompt_hash text NOT NULL,              -- for cache dedup
    user_prompt text NOT NULL,              -- redacted prompt sent to AI
    response    text NOT NULL,
    input_tokens  int,
    output_tokens int,
    cost_usd    numeric(10,6),
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_ai_conv_session ON ai_conversations(session_id, created_at);

-- ========================================
-- REVISJONSLOGG
-- ========================================

CREATE TABLE audit_log (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    workspace_id  uuid NOT NULL REFERENCES workspaces,
    user_id       uuid REFERENCES users,
    action        text NOT NULL,            -- "session.create", "ai.explain", "export.pdf"
    resource_type text,                     -- "session", "workspace", "api_key"
    resource_id   uuid,
    metadata      jsonb DEFAULT '{}',
    created_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_audit_workspace ON audit_log(workspace_id, created_at DESC);

SQLite-ekvivalent

SQLite-adapteren bruker samme tabellstruktur, men uten RLS (enbruker, ingen isolasjon nødvendig), uten gen_random_uuid() (bruker Python-genererte UUID-er), og med TEXT i stedet for uuid-type. Adapteren oversetter mellom de to.

Autentiseringsmodell

# Every request is authenticated via one of:
# 1. Session cookie (web app, after login)
# 2. Bearer token: "Authorization: Bearer lp_live_..." (API key)
# 3. NoAuth mode: auto-authenticated as local user

# Workspace context is resolved from:
# - URL path: /api/v1/workspaces/{slug}/sessions/...
# - OR: API key (implicitly scoped to its workspace)
# - OR: NoAuth mode (auto-scoped to "personal" workspace)

V1 ikke-funksjonelle krav

Observerbarhet: LogPilot må logge seg selv

Et logganalyseverktøy med dårlig logging er en troverdighetskrise

Hvis vi kjører LogPilot som SaaS og ikke kan feilsøke våre egne produksjonsproblemer, har vi et tillitsproblem. Strukturert logging, forespørselssporing og feilsporing må bygges inn fra dag én — ikke boltes på senere.

OmrådeImplementeringFase
Strukturerte applikasjonslogger JSON-formaterte logger via Python structlog. Hver loggoppføring inkluderer: tidsstempel, nivå, request_id, workspace_id, user_id, handling, varighet_ms. Ingen print-setninger. Fase 1
Forespørselssporing Unik request_id generert per API-forespørsel (mellomvare). Propagert til alle tjenestekall, bakgrunnsjobber og AI-leverandørkall. Returnert i svarhoder (X-Request-Id). Fase 1
Feilsporing Uhåndterte unntak fanget med full kontekst (request_id, workspace_id, user_id, stacktrace). I SaaS: sendt til Sentry eller lignende. Selvbetjening: logget til strukturert logg. Fase 2
Ytelsesmålinger Nøkkeltidtakinger logget per forespørsel: parse_duration_ms, analysis_duration_ms, ai_call_duration_ms. Trege forespørsler (> 5s) logget på WARN-nivå. Fase 2
Helse og beredskap GET /health (lever prosessen), GET /ready (er DB + Redis tilkoblet). Brukes av Docker helsesjekker og Kubernetes-prober. Fase 1
Revisjonsspor Allerede i databaseskjemaet: audit_log-tabell. Hver vesentlig handling (opprett sesjon, AI-kall, eksport, inviter medlem) registreres med arbeidsområde, bruker, tidsstempel. Fase 3
AI-kallogging Hvert AI-leverandørkall logget: leverandør, modell, inn/ut-tokens, kostnad, varighet, suksess/feil. For feilsøking og kostnadsovervåking. Allerede i ai_conversations-tabell. Fase 2
Bakgrunnsjobblogging Jobbstart, fremdrift, fullføring, feil logget med job_id, session_id, varighet. Feilede jobber logget på ERROR med full kontekst for feilsøking. Fase 3

LogPilots egne logger bør kunne parses av LogPilot. Hvis vi ikke kan analysere våre egne produksjonshendelser med vårt eget verktøy, har vi mer arbeid å gjøre. Dette er både et kvalitetssignal og en kraftfull demo: «Her er LogPilot som analyserer sine egne logger.»

Produktdesignprinsipper

PrinsippHva det betyr i praksis
Kaskadevisualisering er killer-funksjonen «System A feilet kl. 10:15, noe som forårsaket 47 feil i System B kl. 10:16–10:18, som førte til tidsavbrudd i System C kl. 10:19.» Intet annet verktøy viser dette. ChatGPT kan ikke gjøre det. Gjør det til midtpunktet i demoen og analysevisningen.
Hendelsesrapporten er et artefakt Hver analyse bør produsere en profesjonell, delbar rapport. «Hendelsesrapport — 20. mars 2026 — Databasetilkoblingskaskade.» Merkevareprofil, komplett, klar for post-mortem eller ledelsen. Dette artefaktet sprer kjennskap til verktøyet.
Tom tilstand er førsteinntrykket Før noen logger er lastet opp: vis en eksempelanalyse (ett klikk for å utforske), ikke en tom side med en opplastingsknapp. «Hva slags logger har du?» → velg format → se hva LogPilot finner i den typen.
Feil er muligheter «Kunne ikke parse fil» er en fiasko. «Dette ser ut som et tilpasset format. LogPilot støtter WAS, nginx, Log4j, Python, syslog, Enonic XP og Kubernetes. Lær hvordan du legger til et tilpasset format.» — det er en mulighet.
CLI er en førsteklasses borger logpilot analyze ./logs/ --format markdown og logpilot analyze ./logs/ --explain --provider claude må fungere. Utviklere som lever i terminalen vil ikke åpne en webapp. CLI-en er også den raskeste veien til CI/CD-integrasjon.
Bruk ekte hendelser i hver demo Aldri demo med syntetiske logger. Ta anonymiserte hendelser fra ekte konsulentarbeid. Autentisitet er synlig — og hvis demoen ikke imponerer med ekte data, er det et produktproblem, ikke et demoproblem.
