# Jira & Confluence Integration for LogPilot

## Jira Ticket Generator

### Principle
LogPilot = intelligent underlag, inte automation. LogPilot fyller i det den vet från analysen. Användaren assignar, väljer projekt, kostnadskonto och allt företagsspecifikt.

### Ticket Mapping (automatiskt)

| LogPilot Data | Jira Field | Exempel |
|---------------|------------|---------|
| Primary incident name | **Summary** | "PostgreSQL deadlock caused claims processing outage" |
| Narrative + failure chain + evidence + timestamps | **Description** (markdown) | Full incident beskrivning |
| Confidence score | **Priority** förslag | High conf → P2 Major, Medium → P2, Low → P1 Critical |
| Affected systems | **Labels** | `claims-api`, `postgresql`, `datapower` |
| Suggested fixes | **Acceptance Criteria** | Checklista med åtgärder |
| Suggested team | **Comment/tag** (inte assignat) | "Suggested: DBA" |
| Incident timestamp | **Custom field** eller description | "Incident start: 2026-03-23 10:30:03 UTC" |
| Failure chain | **Description** sektion | "DB deadlock → Pool exhaustion → OOMKilled → 502" |

### En ticket per incident group

Varje Step i analysen blir en potentiell ticket:
- Step 1 (root cause) → Ticket 1 (suggested: DBA)
- Step 2 (concurrent) → Ticket 2 (suggested: DevOps)
- Step 3 (downstream) → Ticket 3 (suggested: Network)

Användaren väljer vilka som ska skapas i en preview.

### Ticket text template (markdown)

```markdown
## Incident: {group_name}

**Status**: {cascade_order} | **Confidence**: {confidence_label} ({confidence_score:.0%})
**When**: {first_trigger_ts}
**Affected systems**: {affected_systems}
**Suggested team**: {suggested_team}

### Root Cause
{narrative}

### Failure Chain
{chain_text}

### Evidence
{evidence_block}

### Acceptance Criteria
- [ ] {fix_1}
- [ ] {fix_2}
- [ ] {fix_3}

### Investigation Directive
{investigate_first}

---
*Generated by LogPilot — {timestamp}*
*Full report attached*
```

### Jira REST API (opt-in)

```python
# Jira Cloud
POST https://{domain}.atlassian.net/rest/api/3/issue
Authorization: Basic {email}:{api_token}

# Jira Server/Data Center
POST https://{server}/rest/api/2/issue
Authorization: Bearer {personal_access_token}

{
    "fields": {
        "project": {"key": "{project_key}"},
        "summary": "{generated_summary}",
        "description": "{generated_description_adf_or_markdown}",
        "issuetype": {"name": "Bug"},  # or "Incident", "Task"
        "priority": {"name": "{suggested_priority}"},
        "labels": ["{system_1}", "{system_2}"],
    }
}
```

### Länkning mellan tickets

Om flera incident groups → skapa Jira issue links:
```python
POST /rest/api/3/issueLink
{
    "type": {"name": "Causes"},
    "inwardIssue": {"key": "PROJ-123"},   # root cause ticket
    "outwardIssue": {"key": "PROJ-124"},  # downstream ticket
}
```

### Streamlit UI Flow

1. Knapp "Create Jira Tickets" under incident overview
2. Preview av alla föreslagna tickets (redigerbar)
3. Checkboxar: vilka tickets ska skapas
4. "Copy to clipboard" (alltid) eller "Create in Jira" (om credentials konfigurerade)
5. Bekräftelse med Jira-länk

## Confluence Integration

### Use Case
Publicera incident-rapporten som en Confluence-sida — "Post-Mortem" eller "Incident Report" i teamets wiki.

### Vad som publiceras
- Full LogPilot HTML-rapport (redan genererad) konverterad till Confluence Storage Format (XHTML)
- Eller: Executive Summary (M61) som en kort Confluence-sida

### Confluence REST API

```python
# Confluence Cloud
POST https://{domain}.atlassian.net/wiki/rest/api/content
Authorization: Basic {email}:{api_token}

{
    "type": "page",
    "title": "Incident Report — {incident_name} ({date})",
    "space": {"key": "{space_key}"},
    "body": {
        "storage": {
            "value": "{html_content}",
            "representation": "storage"
        }
    },
    "ancestors": [{"id": "{parent_page_id}"}]  # optional — place under an "Incidents" page
}
```

### Confluence Storage Format
LogPilots HTML-export behöver konverteras:
- `<details>` → Confluence expand macro
- `<pre>` → Confluence code macro
- `<table>` → fungerar direkt
- CSS/JS → strippa (Confluence har eget tema)

### Streamlit UI Flow
1. Knapp "Publish to Confluence" bredvid "Create Jira Tickets"
2. Konfigurering: Confluence URL + API token + Space key
3. Preview av sidtitel
4. "Publish" → skapar sida, returnerar URL

### Koppling Jira ↔ Confluence
- Jira-ticket description kan länka till Confluence-sidan: "Full incident report: {confluence_url}"
- Confluence-sidan kan lista relaterade Jira-tickets

- Create issue + attachment + links
- ~1.5h

- Confluence-sida → Jira-tickets
- ~30min

## Säkerhet
- API tokens sparas i session state (inte på disk) — eller i environment variables
- PII-redaktion (M59) körs innan ticket/rapport skickas till Jira/Confluence
- Inga lograder i Jira-ticket — bara analyserad data (summering, evidence, fixes)
