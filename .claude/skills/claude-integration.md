# Claude API Integration Patterns

## Prompt Structure

Prompts are built in `logpilot/ai.py` via two functions:

- **`build_claude_prompt()`** — Single-query "Ask AI" prompt. Uses format-aware specialist
  role via `_FORMAT_SPECIALIST` and injects relevant domain skills.
- **`build_cross_system_prompt()`** — Multi-source triage prompt. Builds a per-source
  summary with event counts, top codes/exceptions, and cascade chains.

Both produce `{"system": str, "user": str}` dicts for any AI provider (Claude, Gemini, OpenAI, local).

The system prompt enforces a 4-section response structure:

1. **What this usually means**
2. **Most likely causes**
3. **What to check next**
4. **Confidence / limitations**

## Security (Prompt Injection Protection)

- `_sanitize_prompt_input()` strips XML delimiter tags and escapes entities
- User queries and log excerpts are wrapped in `<user_query>` / `<log_excerpt>` tags
- System prompt explicitly tells Claude to treat these as DATA, not instructions
- `redact()` runs on all event text before it reaches the prompt
- Never include raw unsanitized user input in the system prompt

## Caching

### Ask AI (single queries)

Cache keys are generated by `claude_cache_key()` based on:
- User query (lowercased, trimmed)
- Matched codes, exceptions, tags
- Match type (code/exception/tag/none)

**Do NOT include event text hashes** — same structural match should cache-hit
regardless of minor text variations between log parses.

### Cross-System Triage

Cache keys are generated by `triage_cache_key()` based on:
- Event count, source labels, top codes, exceptions, severity levels
- Model ID (prevents cross-model cache collisions)

Key prefix: `triage:` + SHA-256 hash.

### Two cache layers (shared by both)

1. **Session cache** — per-provider in-memory dicts in `st.session_state`
   (`claude_cache`, `gemini_cache`, `openai_cache`, `local_cache`)
2. **File cache** (`~/.logpilot_cache/ai_responses.json`) — persists across sessions,
   TTL-evicted on load, LRU-evicted to `MAX_CACHE_ENTRIES`

On file cache hit, promote to session cache. Provider prefixes prevent cross-provider
collisions (e.g., `gemini:` + hash, `triage:` + hash).

## AI Content in Exports

All report renderers (`render_markdown_report`, `render_json_report`,
`render_html_report`, `render_pdf_report`) accept an `ai_content` parameter:

```python
ai_content = {
    "triage": str,           # Cross-system triage response text
    "triage_model": str,     # Model name (e.g., "Claude Sonnet 4")
    "ask_ai": [              # Ask AI conversation history
        {"query": str, "answer": str, "provider": str, "timestamp": str},
    ],
}
```

The `_collect_ai_content()` function in `app_render.py` gathers this from session_state.

## API Call Pattern

```python
from anthropic import Anthropic
client = Anthropic(api_key=key)
message = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=2048,
    system=prompt["system"],
    messages=[{"role": "user", "content": prompt["user"]}],
)
```

## API Key Storage

Stored in macOS Keychain via `keyring.set_password("logpilot", "anthropic_api_key", key)`.
Falls back to in-memory session state if keyring is unavailable.
