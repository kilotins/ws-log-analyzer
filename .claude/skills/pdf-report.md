# PDF Report Generation

## Architecture

PDF reports are generated by `logpilot/reports/pdf.py` using the `fpdf2` library (optional dependency). The module follows the same pattern as all report renderers: accepts either individual parameters or a `ReportConfig` dataclass.

## Key Files

| File | Purpose |
|------|---------|
| `logpilot/reports/pdf.py` | PDF renderer — `render_pdf_report()` |
| `logpilot/reports/config.py` | `ReportConfig` dataclass, `REPORT_SECTIONS`, `_sec()` helper, `_report_meta()` |
| `logpilot/reports/__init__.py` | Re-exports all report functions |
| `app_render.py` | Streamlit export UI that calls the renderer |

## Entry Point

```python
from logpilot import render_pdf_report, ReportConfig

# Option A: ReportConfig (preferred)
cfg = ReportConfig(
    events=events,
    top_n=10,
    samples_n=5,
    hist_minutes=1,
    analysis=precomputed_analysis,  # optional, avoids recomputation
    ai_content=ai_dict,             # optional, includes AI sections
    sections={"onset", "causes", "samples"},  # optional, defaults to all
)
pdf_bytes = render_pdf_report(cfg)

# Option B: keyword arguments (backwards compat)
pdf_bytes = render_pdf_report(events, top_n=10, samples_n=5)
```

## Report Sections

Controlled by `REPORT_SECTIONS` keys in `config.py`. Pass a `sections` set to include only specific sections:

| Key | Section | Content |
|-----|---------|---------|
| `onset` | Problem Onset | First error timestamp + type |
| `files` | Per-File Breakdown | File names + event/error counts |
| `levels` | Severity Distribution | Level counters (ERROR, WARN, etc.) |
| `codes` | Message Codes | Top N message codes by frequency |
| `exceptions` | Exceptions/Errors | Top N exception types |
| `tags` | Signal Tags | OOM, HungThreads, DB/Pool, SSL, etc. |
| `causes` | Likely Causes & Fixes | Incident groups, narratives, fixes |
| `hung` | Hung Thread Drilldown | Thread names, stacks, timestamps |
| `timeline` | Timeline | ASCII histogram (events per minute) |
| `samples` | Sample Events | Labeled representative events |
| `ai` | AI Analysis | Incident analysis + previous queries |

## PDF Structure

### Branding
- **Header**: Report title (left) + "item.no" (right) + divider line
- **Footer**: Page numbers (left) + "Powered by LogPilot - Item Consulting" (right)
- **Colors**: Slate palette (#1E293B body, #64748B subtitle, #94A3B8 header/footer)
- **Fonts**: Helvetica (body), Courier (monospace/code blocks)

### Page Flow
1. Title page: report name + subtitle (files, time span, event count)
2. Problem onset (if detected)
3. Per-file breakdown (multi-file only)
4. Severity levels → codes → exceptions → signal tags
5. Likely causes with incident groups (triggers, effects, narratives, fixes)
6. Hung thread drilldown (if any)
7. Timeline histogram (compacted for large datasets)
8. Sample events (with metadata and sanitized text)
9. AI analysis (new page, includes model name and query)

## Gotchas

### Encoding
- fpdf2 core font support is latin-1 only. All text passes through `_latin1_safe()` which replaces unsupported Unicode with `?`.
- For full Unicode (CJK, Cyrillic, emoji), you'd need `pdf.add_font()` with a TTF file — not currently implemented.

### Text Truncation
- Sample event text is capped at `MAX_EVENT_TEXT` (from `parser.py`, typically 4000 chars).
- Monospace blocks wrap at 110 characters per line to fit the page.
- AI analysis text is not truncated — can produce many pages.

### Dependencies
- `fpdf2` is an **optional** dependency. Import fails gracefully if not installed.
- Install: `pip install fpdf2`
- The CLI does NOT support PDF export — only Streamlit and programmatic API.

### ReportConfig Pattern
All four renderers (markdown, html, json, pdf) accept `ReportConfig` as the first positional argument OR individual kwargs. When modifying one renderer, keep the dual-input pattern consistent:

```python
def render_pdf_report(
    events: list[LogEvent] | ReportConfig | None = None,
    top_n: int = 10, ...
    config: ReportConfig | None = None,
) -> bytes:
    if isinstance(events, ReportConfig):
        config = events
        events = None
    if config is not None:
        events = config.events
        # ... unpack other fields
```

## Extending the PDF

### Adding a New Section
1. Add key to `REPORT_SECTIONS` in `config.py`
2. Add `if _sec(sections, "my_key"):` block in `pdf.py`
3. Use `heading()`, `body()`, `mono()`, `bold_line()` helpers
4. Add corresponding blocks in `markdown.py` and `html.py` for consistency

### Adding Charts/Images
```python
# fpdf2 supports images from bytes
import io
from matplotlib import pyplot as plt

fig, ax = plt.subplots(figsize=(6, 2))
# ... draw chart
buf = io.BytesIO()
fig.savefig(buf, format="png", dpi=150, bbox_inches="tight")
buf.seek(0)
pdf.image(buf, w=170)
```

### Custom Fonts
```python
pdf.add_font("Inter", "", "fonts/Inter-Regular.ttf")
pdf.add_font("Inter", "B", "fonts/Inter-Bold.ttf")
pdf.set_font("Inter", "", 9)
# Now full Unicode works
```

## Testing

PDF tests use `fpdf2`'s output — assert on byte length and basic structure:

```python
def test_pdf_report():
    pdf_bytes = render_pdf_report(events)
    assert pdf_bytes[:4] == b"%PDF"
    assert len(pdf_bytes) > 1000

def test_pdf_sections():
    cfg = ReportConfig(events=events, sections={"causes", "samples"})
    pdf_bytes = render_pdf_report(cfg)
    assert b"Likely Causes" in pdf_bytes
```

Existing tests: `tests/test_reports.py` covers all four formats including PDF.
